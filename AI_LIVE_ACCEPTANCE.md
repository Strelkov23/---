## Проверка публичной сборки

Из локального клона репозитория после завершения публикации:

```sh
python3 site/probe_ai_public_release.py --base https://strelkov23.github.io/---/ --revision <ФАКТИЧЕСКАЯ_РЕВИЗИЯ>
```

Проверяются восемь условий: исходная ревизия, точные байты трёх скриптов и наличие элементов помощника на четырёх страницах. Для последующих релизов указывать фактическую исходную ревизию, а не ревизию архивного коммита. В GitHub Actions независимую проверку можно запустить вручную через AI live release probe checks, указав ту же ревизию. Скрипт не загружает модель, не отправляет вопросы внешним каталогам и ничего не изменяет.

## Проверка пользователем

1. Открыть помощника на главной, исторической странице, странице литературы и в аналитическом центре. Проверить отправку, отмену, переключение диалогов и отсутствие горизонтальной прокрутки.
2. Без модели выполнить архивный запрос «Производительность труда: 2025; база=2019». Проверить период, происхождение данных и ссылки; уточнить «А за 2024 год?».
3. Ввести «Найди в интернете историю вычислительной техники». Отклонить подтверждение, затем повторить и подтвердить. Проверить ссылки, отсутствие результата при недоступности каталога, разграничение метаданных и утверждений авторов.
4. На устройстве с WebGPU загрузить один профиль модели. Открыть «Диагностика качества локальной модели»; записать профиль, браузер, устройство, итог из девяти задач и время каждой. Повторить минимум дважды. Не считать искусственный транспорт или успешный запуск доказательством качества модели.
5. В реальном диалоге проверить русский язык, объяснение межотраслевого баланса, уточняющий вопрос, противоречивые данные и признание нехватки информации. Оценивать содержательность вручную.
6. Повторить на мобильном устройстве. Если WebGPU не работает, проверить поиск без модели; зафиксировать недоступность общего чата как ограничение устройства.

## Критерии

Техническая приёмка: успешный deploy и восемь проверок публичной сборки. Практическая приёмка: зафиксированы результаты фактического запуска модели и внешних источников, выявленные ошибки классифицированы. Для исследования качества недостаточно девяти синтетических задач. Не заявлять паритет с ведущими универсальными моделями, полный веб-индекс, автономное получение всех данных или работоспособность на всех устройствах.
